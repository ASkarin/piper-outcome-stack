## 研究问题

1. 在任务 A 的冻结数据、状态/action schema、划分和评测预算下，ACT 能否形成跨 seed 可重复的实机成功率基线？
2. 在任务 B 的相同数据和预算约束下，SmolVLA 能否改善语言改写或 OOD 泛化，并保持可接受的控制精度和延迟？
3. 动作结果模型能否在执行前识别有害失败，并在闭环介入时减少有害失败而不过度终止本可成功的回合？

## 任务与冻结边界

- 任务 A：多位置抓取放置。具体对象、位置、目标边界、稳定时长、时限和容差在 20 条试轨迹审计后、正式采集前冻结。
- 任务 B：语言条件分类放置。对象类别、语言模板、改写/OOD 列表、容器和时限与任务 A 的场景冻结同时完成。
- 任务 C：条件任务。仅在 2026-10-04 gate 同时满足 PiPER 安全采集链路通过、任务 A 有可重复 ACT 基线、且不挤占结果模型和冻结评测时，另建 amendment 后采集 100—150 条；未通过仅作探索展示。

## 数据、指标与停止规则

- train 只用于拟合；development 用于实现、诊断和预登记调参；validation 用于候选 checkpoint、阈值和 gate；final test 只对最终冻结方案运行一次。
- 同一轨迹、裁剪片段和强相关 session 不得跨划分。final test 不得回流训练或选择。
- 任务 A/B 主指标为逐回合二元成功率并报告 95% Wilson 区间。结果模型报告 AUPRC、AUROC、Brier score、校准误差、失败类型召回率、可用提前量、rescue 和 harmful abort。
- 出现越界、零位漂移、急停或停止策略失效、通信故障、反馈过期、相机/同步故障时立即停止。修复并重新通过相应 gate 后才能继续。
- 每个训练 spec 在运行前冻结 commit、数据版本、seed、`max_steps`、`max_wallclock_seconds`、`eval_interval_steps`、`patience_evaluations` 和 `stop_metric`。不得根据 final test 延长训练。

## PiPER 硬件 gate

motion 必须依次通过：身份/固件/夹爪/线束/USB-CAN/物理急停核验；五次只读连接；通信中断、watchdog 和防坠落停止策略验证；单关节低速小增量；六关节与夹爪；Xbox hold-to-run；双相机同步与 30 分钟稳定性；至少 20 个连续安全遥操作回合；20 条试轨迹 record/finalize/reload/replay 和质量审计。

实物不是标准 PiPER，或物理急停/停止策略不成立时，motion gate 保持关闭并回到项目决策。不得自动尝试其他型号或固件。

## 禁止事后调整

查看 final test 后不得改变模型、checkpoint、seed、训练数据、阈值、action chunk、归一化、相机布局、schema、成功定义、指标、统计方法、排除规则或回合预算。实现缺陷导致评测无效必须保留事故和原结果，并以新冻结版本和未接触 holdout 重做，不得覆盖。
