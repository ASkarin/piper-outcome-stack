## 1. 配备与软件能力

当前默认一台 D435，不是程序永久硬件限制。逻辑相机名称、数量、设备选择、RGB/深度开关由配置指定。现阶段复用官方 RealSense 后端，可使用序列号或唯一设备名；名称歧义由实际设备选择处理，不要求预先验收声明。其他后端尚未实现，不宣称已支持任意相机。

记录必要的实际设备身份、profile、内参、RGB/depth 外参和时间信息。尺寸、字段冲突、配置流缺失、非有限数据、重复/过期帧等有实际后果的问题仍明确报错；不因改名或启用深度报错。

## 2. 采集与模型输入分离

- 公共关节 state/action 仍为七维 rad/m；时间、设备尺度和内外参不进入这七维。
- 对逻辑相机 name，RGB 观测为 name，深度为 name.depth；Dataset 对应 observation.images.name 与 observation.images.name.depth。
- RGB 对外统一 RGB 顺序；数值深度为 float32 米、H×W×1，使用无量化 TIFF 存储；即使 RGB 使用视频，深度也不走默认 12-bit 视频量化。
- 原始 uint16 Z16、实际 depth_scale_m 和形状与逐帧 session/episode/frame/attempt 关联保存，保证可以核对原始计数。额外原始文件是深度来源，不建立第二套 Dataset 生命周期。
- 深度保持 native 像素网格；保存原始内参、深度到彩色的旋转/平移与图像旋转信息，不声称已逐像素对齐或相机到机器人外参已标定。零值保留为无效深度，不填补孔洞。
- 继续记录设备帧号/时间/时钟域与共同主机接收单调时间，不将 frameset 当作硬件曝光同步证明。
- 相机帧率可以高于 Dataset 采样率；不要求完全相同。采样率不能超过配置流的供帧率，不重复图像凑帧；实际吞吐和时序质量仍需现场测量。

## 3. 训练与评测

默认 RGB 基线仅选择七维状态与 RGB 图像；采集到深度不等于模型必须使用它。项目 train 入口只在从头训练且未显式指定输入时选择 RGB，随后调用官方训练函数；显式输入、预训练 checkpoint 与 resume 继续采用各自定义，不自动改写。

原生 lerobot-train 仍可使用，但对含深度的 Dataset 应显式设置 policy.input_features，不能把上游“从所有数据字段推断”误认为 RGB 选择。RGBD 编码器/深度分支属于后续模型实现，不把一通道深度或第四通道直接塞给未经适配的 RGB checkpoint。

正式实验必须记录实际采集字段与实际消费字段；RGB-only、RGBD、几何辅助各自披露使用的深度信息。对照组保持规定的任务、数据预算和评测条件，新增视角/模态作为明确实验变量，不事后改变测试难度。

## 4. 数据与版本

新增深度或更改数据字段后使用匹配的新 Dataset schema/版本；不回写旧 RGB 数据、补造深度或覆盖失败记录。续录核对实际字段、形状、深度标记与单位，不要求设备名称永远不变，但已有 Dataset/checkpoint 的字段契约必须匹配。

深度文件写入失败、中断或缺少原始来源不标记完整；重录保留弃用 attempt 的诊断文件，审计只接受已保存 attempt。算法训练、硬件运动与正式 release 不由本次修订自动启动。项目截止日、每周容量和既有成功定义保持，删除重复的单设备限制与相应测试，不增加额外采购或强制采集任务。
