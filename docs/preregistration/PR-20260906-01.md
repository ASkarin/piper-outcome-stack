## 1. 研究问题

1. **ACT 实机基线**：在任务 A 上，固定数据版本、观测、动作表示和评测预算后，ACT 能否形成跨 seed 可重复的实机成功率基线？
2. **SmolVLA 适用边界**：在与 ACT 相同的数据、相机、状态、划分和预算下，SmolVLA 是否改善任务 B 的语言改写或 OOD 泛化，同时保持可接受的精细控制和延迟？
3. **动作结果模型**：给定当前观测、机器人状态、任务指令和候选动作块，结果模型能否提前识别有害失败，并在闭环介入时降低有害失败而不过度终止本可成功回合？

这些是假设而非预设正向结论。SmolVLA 或结果模型无稳定收益时保留完整负结果。

## 2. 冻结机器人与策略接口

- 硬件范围：标准 PiPER 六轴机械臂与官方夹爪；不自动兼容其他型号或固件。
- observation/action：`joint_1.pos`…`joint_6.pos`（rad）与 `gripper.pos`（官方夹爪总开口宽度，m）。
- 首版策略状态不含 velocity、effort 或 TCP pose。唯一图像键为 `observation.images.d435`，单台 D435 的 RGB、H×W×3、uint8；action 与 observation.state 仍各为 7 维。深度用于相机验收和标定，不进入首版 ACT/SmolVLA/结果模型输入。
- 固定外置视角，在试采集前确认抓取点、夹爪与目标区域可见；准确安装位置、序列号、分辨率、帧率、曝光与标定在现场冻结。ACT 与 SmolVLA 使用同一份 RGB/状态输入和预处理。
- 故障码、接收频率和时间戳单独记录；相机帧与机器人状态/动作的主机时间映射必须实测，不把单相机或 nominal fps 相同写成同步已经通过。
- Xbox processor 在数据写入前将 XYZ+yaw+夹爪增量转换为唯一 7 维 action schema；roll/pitch 每次会话开始时锁定。
- observation/action schema 若在 20 条试轨迹审计后改变，必须在正式任务数据开始前创建 amendment；正式数据开始后改变则新建 major 数据版本和预注册。

## 3. 任务与结果语义

### 任务 A：多位置抓取放置

成功：在冻结时限内抓取正确对象，将其完全释放并稳定留在目标区域；无策略导致的故障锁存、人工接管或越界动作。失败包括漏抓、掉落、错误区域、未完全释放、超时、策略故障或人工接管。

### 任务 B：语言条件分类放置

成功：执行对象与指令语义一致，并满足任务 A 的稳定放置与安全条件。失败包括错误对象/类别、未稳定放置、超时、策略故障或人工接管。

### 任务 C：接触敏感任务

任务 C 保留条件范围。2026-10-04 只有在 PiPER 安全采集链路通过、任务 A 有可重复 ACT 基线、且不会挤占结果模型与冻结评测时才进入正式范围。通过后在查看任务 C 正式结果前创建 amendment，冻结堆叠、精确放置或宽松公差插入中的唯一任务及 100—150 条计划；未通过则只作探索或展示，不纳入最低成功标准。

## 4. 指标与统计

- 任务 A：逐回合二元成功率。
- 任务 B：指令一致完整成功率，以及相同预算下 SmolVLA−ACT 差值。
- 结果模型离线：AUPRC 为主，同时报告 AUROC、Brier score、校准误差、失败类型召回与提前量。
- 结果模型闭环：任务成功率和有害失败率共同为主，报告 rescue 与 harmful abort。
- 二元成功率报告 95% Wilson 置信区间；跨条件按冻结的任务×条件单元等权；模型差值使用分层 bootstrap。
- 次指标：ID/OOD 差、完成时间、接管率、failure taxonomy、感知/模型/通信/发送/总闭环 P50/P95/P99、控制抖动、推理显存、吞吐和训练资源。

结果模型工程门槛在 validation 前结合硬件基线冻结；当前不预填成功声明。

## 5. 划分与冻结 gate

| 划分 | 唯一用途 | 规则 |
|---|---|---|
| train | 模型拟合 | 使用冻结清洗规则 |
| development | 实现、超参数和失败诊断 | 可重复使用；正式调参有实验 ID |
| validation | checkpoint、阈值和 gate 决策 | 访问须记录；不回流同版本 train |
| final test | 冻结方案的一次性报告 | 阶段 5 封存，阶段 6 才运行 |

- 同一轨迹、裁剪片段、采集 session 和强相关 source trajectory 不跨划分。
- 20 条试轨迹只用于链路/质量审计，不默认进入正式数据。
- 正式采集前冻结 A/B 对象、位置、背景/光照、单台 D435 布局、语言模板、容差、时限、划分与最低预算。单视角抓取遮挡计入失败分析，短时遮挡评测继续保留，不靠添加视角或删除困难回合降低难度。
- 关键观测消融采用同一 RGB 下的状态或历史信息消融；不设置第二视角条件。任务 C gate 额外核对该任务在单视角下能否可靠观测与判定成功，其他 gate 不变。
- 正式数据、模型或配置若仍含其他相机键，不做补零、复制图像或别名转换；保留原始工件与登记，使用本预注册重新建立匹配的数据/模型版本。
- 阶段 5 结束前生成 final freeze，绑定具体 final test 清单和全部资产哈希。
- 策略造成的通信异常、故障锁存、超时或相机失败计为失败。只有预注册覆盖的外部故障可标无效，且保留日志/视频并按冻结顺序补跑。

## 6. 硬件与安全 gate

motion 前必须完成：

1. 标准 PiPER 铭牌、序列号、准确固件、官方夹爪、电源/线束和官方 USB-CAN 清点；
2. 物理急停存在且现场有效；底座固定、负载和工作区明确；
3. 五次只读连接可稳定读取六轴和夹爪反馈；单位、频率、时间戳新鲜度正确；
4. 通信中断、watchdog 和停止动作经现场验证，不导致机械臂坠落；
5. 冻结硬件身份、关节/夹爪限位、单步增量、反馈超时及工作空间；
6. motion 配置与验收记录完全匹配。

实机身份不符、急停缺失或停止策略不成立时 motion 保持关闭，不自动切换型号、固件或 SDK。

## 7. 停止规则

1. 未解释越界、零位漂移、急停失效、停止导致下落或通信异常时立即停止，修复并重新通过 gate。
2. A/B 各先采 20 条并审计，再扩到 50 条；每新增 100 条高质量示范后 development 主指标提升小于 5 个百分点时暂停扩采并诊断。
3. 每个训练 spec 预先冻结 `max_steps`、`max_wallclock_seconds`、`eval_interval_steps`、`patience_evaluations` 和 `stop_metric`；不得根据 final test 延长。
4. SmolVLA 最多两轮预先登记且各有明确假设的调参；仍不稳定则冻结负结果并转入结果模型。
5. experiment identity 完全一致才可沿用 attempt；代码、配置、seed 或数据变化必须新建实验。旧 checkpoint 作为 `warm_start` 时显式登记。
6. 所有失败、拒绝和提前终止生成结果摘要与 `stop_reason`，不得从索引删除。

## 8. 最终冻结与禁调项

final freeze 至少绑定：本预注册、划分/评测协议、Git commit、环境、配置、seed、停止参数、数据版本/清单、checkpoint、归一化、标定、相机、硬件/安全配置、action chunk、阈值、回合预算、运行顺序、随机化、成功定义、指标、置信区间、failure taxonomy、排除规则和 final test 清单。

查看 final test 后禁止调整模型、checkpoint、seed、数据、阈值、action chunk、归一化、相机、标定、观测、动作、语言、任务容差、清洗、划分、指标、统计、failure taxonomy、预算、顺序、排除规则、条件权重或展示视频。实现缺陷使评测无效时保留原结果，建立新预注册/freeze 并使用未接触 holdout。
