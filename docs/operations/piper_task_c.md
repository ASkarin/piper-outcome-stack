# 阶段 C：Push‑T

当前从操作者定义的第三种起始姿态 `start-03` 推到有三个角标的 G。位置和朝向均对齐，夹爪撤开后 T 保持对齐，记录为成功。待这一条件下的策略取得实机成功后，再扩展起点。

在控制机现场终端启动采集：

```bash
piper record c
```

训练命令从常规档（`normal`，100%）开始，本会话采满 50 条有效成功示范后结束。补采开发示范另开会话，用 `piper record c --split development`，同样从常规档开始，目标为新增 6 条。与已核对的两条精细档开发示范合计 8 条。

按第三种参考图复位，松开 LB、摇杆和扳机回中，保持确认后输入 `3`。Xbox 的 **X 在平移模式下切换腕部优先保持 / 保持朝向平移**，**三横线 ≡ 切换常规 100% / 精细 50%**。新会话初始为常规档，可直接按住 LB 接近 T 块。接触前松 LB、回中、等保持确认，点 ≡ 切到精细档，然后按 LB 推动和调角。当前档位见终端，并在同一会话内跨回合保留。侧向撤开使三个角标可见，观察末态后松开 LB，输入 `end`。审阅时 `1` 保存成功，`2 备注` 保存失败，`3 备注` 保存取消，`r` 放弃本次重录。等待保存完成，复位后再输入 `3` 录下一条。

每条按一次完整复位和人工结果计数。成功回合按有效帧记录常规和精细两个档位的数量。含有效精细档操作的混合档或纯精细档成功回合占一个名额；整条来源示范的有效接近、推动和退出片段一起保留。纯常规档单列。准备界面输入 `q` 可提前封存；重开命令会创建独立会话并从零显示进度。分批采集时，在最后一个会话达到剩余条数后输入 `q`。

采集使用活动 operator profile 中的 `record_c_config`。D435 彩色流和状态/实际下发动作保留，阶段 C 部署配置关闭深度流和深度导出。默认控制/Dataset 50 Hz，彩色流 640×480 / 60 fps。记录文件位于各自根目录的 `task-c/train/` 或 `task-c/development/`。终端打印的 Session 是含 config.json 的会话目录。

```bash
piper convert <Session目录>
piper audit <Session目录>
```

`python -m piper_outcome_stack.task_c manifest --session <Session目录> --output <新文件>` 可汇总已转换会话。每段保留来源、起始/目标参考及真实任务文本，成功且有效的示范进入行为克隆候选。失败、取消和接管分别记录。旧 G 的三次开发试推归档在原场景。

## 从 start-03 试推一轮

在控制机运行 `piper c check`，使用活动配置核对训练机导出的 FP32 首块、RTC 续块和投影目标。每个前缀都由控制机自己的首块构造。两端在同一录制输入和种子下的关节差须小于 0.0001 rad、夹爪差须小于 0.00001 m。检查报告同时列出录制目标的数值约束结果。

将 T 块按第三种起始参考图摆好。机械臂使用采集示范时保存的 A 工作位。确认到 A 的路径无遮挡，在控制机启动本轮。

```bash
piper c run
```

命令会再次核对 FP32 参考并显示 A 的关节角和夹爪目标。松开 LB，摇杆和扳机回中，确认路径后按回车，机械臂将使能、建立保持并回到 A。回 A 全程保持 LB 松开，期间按 LB 或推动摇杆会取消准备并请求保持。依次看到 `[回A完成]` 和 `[策略就绪]` 后，再按住 LB 启动推 T。松开 LB 会结束本轮并保持当前位置。B 用于紧急停止。对齐 G 三个角标且夹爪撤开后松开 LB，按现场结果标注。输入 `1` 表示成功，`2` 表示未完成或程序故障，`3` 表示外部条件使试次无效，并填写相应说明。每次命令只运行一轮。

两条命令共用全 FP32 参数、关闭自动混合精度和 TF32、固定 cuDNN 卷积设置的推理过程，执行沿用 50 Hz 和 25 tick 请求间隔。活动配置的 `policy.reference_inputs.push_to_G` 指向训练端导出的 NPZ。每组包含 RGB、七维状态、指令、两次采样的种子以及 FP32 首块、带前缀原始块和带前缀投影块。起始和目标参考图供现场复位及标注使用。


## 同一场景比较策略

控制机的 `piper c check` 和 `piper c run` 默认使用 original。候选模型的检查和运行使用相同的选择参数，例如 `piper c check flat`、`piper c check act`。通过检查并准备在现场测试后，操作者可运行 `piper c run flat` 或 `piper c run act`。候选配置由活动 operator profile 的 `c_policy_configs` 指定，各次报告保存实际 checkpoint、模型类型和执行参数。

两种 SmolVLA 均用 FP32 和原 RTC 配方。ACT 从观测状态还原七维绝对动作块，50 Hz 下每步预测，在绝对目标上用系数 0.01 做时间集成。其跨机参考包含完整动作块和连续两次请求产生的集成目标。三者共用回 A、LB 放行、B 急停与实时动作检查。
