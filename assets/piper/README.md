# PiPER S0/S1 model sources

- Official source: https://github.com/agilexrobotics/agx_arm_urdf/tree/f6642ce0d7872c686f29c99e9e10cd23d1d49313
- `upstream/`: standard PiPER URDF and gripper Xacro from `piper/urdf/`; line endings/trailing whitespace normalized, XML semantics unchanged.
- `meshes/`: only the eleven referenced STL files from `piper/meshes/`.
- `LICENSE`: upstream MIT license. Existing notices remain in `licenses/` and `THIRD_PARTY.md`.
- `piper.xml`: deterministic MJCF generated by `python -m piper_outcome_stack.sim.model`; no ROS or general Xacro runtime required.

The converter preserves joint origins/axes and original inertials. STL collision meshes are also used for plain visualization. Directly adjacent bodies are excluded from collision; other contacts remain observable. MuJoCo convex mesh contacts are not a validated model of the full real contact geometry.

The massless `gripper` control coordinate is omitted. The two physical finger joints keep their original origins and axes, with q2 = -q1, and total width = q1 - q2. The public action remains six radians plus total width in metres, while the model has eight physical generalized coordinates and seven actuators.

Controller angle ranges previously read during PiPER commissioning are [-150,0,-170,-100,-70,-180] to [150,180,0,100,70,180] degrees. Simulation uses their intersection with this URDF, notably retaining the narrower J6 [-120,120] degree model range. This does not write or expand any real safety limits. URDF force limits and 2 Hz mass-matrix-derived servo gains are simulation-only, unidentified parameters.

`sdk_fk_reference.json` contains 18 numerical FK outputs evaluated with the existing pinned SDK `799b8412fbe8b9156bc9892d3dbeb2df7e98be71`, calling only `get_mdh('piper')` and `fk_from_mdh`. No robot object or CAN connection was created. It is an independent SDK-model comparison, not a second FK control implementation or a physical accuracy measurement. Reports retain MDH/URDF differences instead of forcing them to agree.

The example tabletop and virtual camera are illustrative and uncalibrated. No simulation data in this directory is a real Dataset episode or a hardware acceptance result.
